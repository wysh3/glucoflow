# Deployment and operations

## Services

| Service | Host | Responsibility |
|---|---|---|
| Frontend | Vercel static deployment | Vite assets and SPA route fallback |
| API | Railway Node container | Token verification, authorization and transactions |
| Worker | Railway separate Node container | PDF/OCR, model calls, export and durable retries |
| Database/Auth/Storage | Supabase | Private records, sessions and files |
| Android | Signed APK distributed privately | Bundled frontend assets and native camera bridge |

This is a deployment recommendation, not a claim that accounts or services exist. Choose compatible available regions and measure round-trip latency. Configure spend limits before enabling model processing. Do not provision paid plans without explicit authorization.

## Environment contract

Frontend public: `VITE_API_BASE_URL`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_DEMO_LABEL`. These are public configuration, not privileged credentials.

API private: `SUPABASE_URL`, `SUPABASE_JWKS_URL`, `SUPABASE_STORAGE_SERVER_KEY`, `DATABASE_URL_API`, `ALLOWED_ORIGINS`, `APP_ENV`, `UPLOAD_MAX_BYTES=15728640`, `UPLOAD_MAX_PAGES=10`.

Worker private: `DATABASE_URL_WORKER`, `SUPABASE_URL`, `SUPABASE_STORAGE_SERVER_KEY`, `EXTRACTION_PROVIDER`, `EXTRACTION_MODEL`, `EXTRACTION_API_KEY`, `MAX_DOCUMENT_MODEL_CALLS=12`, `MAX_DOCUMENT_COST_USD`, `MAX_RUN_TOKENS`, `WORKER_CONCURRENCY=2`.

Do not log values of these settings. `.env.example` includes names and harmless placeholders only. Storage server keys stay in authorized server-side modules, never a shared client import. Use separate credentials for API and worker with minimum practical scope. The worker must not expose an HTTP route that accepts arbitrary external source URLs.

## Authentication persistence

Use Supabase email/password sign-in for seeded demo accounts. Browser session persistence uses the SDK-supported adapter with strict CSP and no untrusted HTML injection. Native persistence must use an audited Capacitor secure-storage adapter backed by Android Keystore; verify its compatibility and license during implementation. Do not put refresh tokens into plain Capacitor Preferences. If the adapter is not available, use memory-only sessions requiring sign-in after restart and disclose that limitation rather than falling back silently.

No public sign-up or unreviewed self-assignment of roles. Sign out the current device session, clear its query caches and remove temporary source files. Do not sign out other devices as an unexpected side effect. Configure this scope explicitly in the Auth SDK.

## Upload and file handling

Private source bucket and private export bucket. Object keys generated by server and scoped by clinic/patient/document IDs. Validate file signatures independently of extension or user-supplied MIME. Reject encrypted PDFs with an actionable message. Limit temporary disk, image size, PDF pages, parser CPU and memory. Never execute PDF scripts or render uploaded HTML. Worker containers run as non-root with constrained resources. Remove temporary files in success and failure paths.

No offline patient-record persistence in MVP. App shell can load from APK without network; data screens show offline state. Keep unsent form values in memory only. Warn on user-initiated navigation with unsent changes. Operating-system process termination cannot guarantee a warning or recovery. On resume fetch upload/job state using server-issued IDs. Release camera temporary files after completion/cancel where platform APIs permit it.

## API controls

HTTPS only in deployed environments. Explicit browser/Capacitor origin allowlist. Bearer-authenticated endpoints do not accept unauthenticated ambient mutations. Rate-limit sign-in attempts through configured auth controls, upload creation to 10 per user per minute, and retries to 3 per document per hour. Pagination limits prevent unbounded record reads. Sanitize filenames used in headers. Never interpolate extracted text into HTML.

## Database and migration order

Run migrations against a disposable environment first, including policy tests. Apply additive migrations before new application code. Keep old clients compatible through `/api/v1`; reject unsupported schema versions with a clear upgrade message. Roll back application releases only when the previous version still understands the database. Never automatically drop clinical tables to reverse a deployment.

Seed two isolated synthetic clinics for authorization checks, one demo patient/clinic account pair and a reviewer/clinician account. Seed script must require explicit demo environment and clinic ID. Reset script refuses a non-demo tenant. No public reset endpoint.

## Operational endpoints and checks

`GET /health/live`: process alive, no secrets. `GET /health/ready`: bounded DB connectivity check with generic status. Internal worker heartbeat: last successful lease loop, queue age and failure counts in restricted operational logs. The public health endpoint never returns medical rows or connection strings.

Healthcheck the API, confirm worker heartbeat, upload a synthetic report, complete review, generate an export, then confirm the patient view. Test source denial from the other clinic. A green HTTP healthcheck is not evidence of a functioning extraction pipeline.

## Planned commands

The build tasks must create and document these scripts:

- `pnpm dev`: client/API/worker using local environment.
- `pnpm typecheck`, `pnpm test`, `pnpm build`: quality gates.
- `supabase test db`: database isolation and constraints.
- `pnpm seed:demo --clinic <id>`: create isolated fixtures.
- `pnpm reset:demo --clinic <id> --confirm-demo`: reset only flagged demo data.
- `pnpm smoke --base-url <url>`: authenticated synthetic smoke flow.
- `pnpm --filter client build` then `pnpm --filter client exec cap sync android`: bundle Android assets.
- Build a signed release APK with Gradle using private keystore configuration; document the exact command after native project generation.

Signing keys and passwords stay outside Git. Confirm Android package ID with the user before external store publication; internal MVP package ID proposal is `in.sutra.demo`. Store publication is outside this plan.

## Observability and retention

Use opaque IDs in operational logs. Capture real duration, error code and retry count. Restrict access to model run details and document content. Model inputs are synthetic during development. No compliance certification is claimed by using encryption or Supabase.

For the demo environment, schedule removal of uploaded demo files and generated exports after 30 days, using a required maintenance command, with corresponding DB cleanup by an authorized maintenance job. Audit metadata may retain non-content technical events for 90 days. These are demonstration retention defaults, not a medical-record retention policy. Configure actual deletion/backup behavior before claiming erasure guarantees. Future ABHA consent and real-clinic retention require a separate approved design.

## Remaining gates

Live extraction credentials/budget, hosting access, signed APK installation, actual Android device checks and clinician workflow evaluation. Do not mark the app complete when any required live flow only works with fixtures.

References: [Railway Fastify deployment](https://docs.railway.com/guides/fastify), [Capacitor Android](https://capacitorjs.com/docs/android), [Supabase storage access control](https://supabase.com/docs/guides/storage/security/access-control).

## Maintenance tasks

Implement `pnpm maintenance:demo --dry-run` and a separately authorized `--apply` mode. Remove orphaned upload objects only after 3 hours and completed demo content after the 30-day retention window. Remove dependent draft facts, evidence and export manifests transactionally in a documented order. Preserve only non-content audit events for at most 90 days. Cleanup checks the demo tenant flag and refuses non-demo records. Emit aggregate counts, not content. Verify actual backup retention separately before making an erasure claim.

API response `Cache-Control: no-store` applies to records and signed-URL responses. The service worker, if added for the shell, must exclude API, source and export requests. Never embed signed source URLs into telemetry.
