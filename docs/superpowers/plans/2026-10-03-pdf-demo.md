# PDF dashboard and hackathon demo implementation plan

Authority: user's explicit request to implement the supplied PDFs exactly and provide
credential-free role entry. This supersedes the previous exclusions for home telemetry,
calendar tracking, configured flags, manual care categories and demo SOS snapshots.
Implement directly in this workspace, without agents.

## Design

Keep existing verified authentication, review/publication, source records and graph views.
Add a Master dashboard matching the PDF's dual-axis chart, exact annual/Q2 values,
medication phases, renal/lipid summaries, safety/compliance cards and manual 80/20
operational category. The supplied scenario is explicitly synthetic; period-only dates
stay period-only. No invented quarterly observations or inferred treatment causation.
Patient home readings and timestamped symptom/severity entries persist as append-only
JSON events. SOS captures a frozen snapshot and sends it to the authorized demo clinic
desk; it never contacts real emergency services. Clinicians can acknowledge snapshots,
set screening dates and select a manual care category. Fixed 365-day/default rules are
configured review rules, not diagnosis or proof that a test never occurred.

Demo role buttons sign into the six intentionally public synthetic demo accounts using
the existing local/Supabase Auth path. No privileged credentials or role bypass.
The prototype keeps existing upload, review and source evidence flows available.

## Claim handling

Keep supplied headings/reference labels in the reproduction. Label supplied numbers,
regimens, dates and thresholds as illustrative scenario/configuration. The 30-second
view is a design target, not measured productivity. Immutable means append-only in the
application with a SHA-256 snapshot digest; storage administrators retain technical
control. No emergency-response delivery claim beyond the demo clinic inbox. References
are for clinician review and do not label a patient's diagnosis.
