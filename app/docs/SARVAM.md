# Sarvam speech integration

Official API and policy sources checked 7 November 2026. This note covers the REST speech models, the provider's account controls and the separate options for serving a reasoning model. The research below is based on documentation and source inspection. Subsequent implementation and the separately authorized synthetic live check are recorded at the end.

## Product boundary

Use Sarvam Model APIs at the speech boundary. A user records a short clip, chooses to transcribe it, edits the resulting draft and explicitly submits text through the existing GlucoFlow flow. The microphone and the transcript grant no authority to create a clinical fact, approve an action, change a source document or publish a workflow. Disclose that Sarvam receives the recording before dispatch. Demo prompts and spoken examples use synthetic information.

Playback starts only when a user chooses to hear a permitted, reviewed block of text. Send the exact authorized display text and its spoken-language code to synthesis. Keep the visible source text and citations authoritative. Audio is a synthetic rendition and pronunciation can differ, especially for units, names, dates and numbers. App interface language comes from local message catalogs. The selected locale reaches the existing Hermes system prompt on the same Ask turn. The validated renderer currently supports English and Hindi and labels English fallback for other selections. Use the reply's actual language for playback. Source records and editable transcripts stay in their original text.

## Speech API contracts

| | Editable speech draft | Explicit read-aloud |
| --- | --- | --- |
| Endpoint | `POST https://api.sarvam.ai/speech-to-text` | `POST https://api.sarvam.ai/text-to-speech` |
| Authentication | Server-side `api-subscription-key` header | Same header |
| Request | Multipart `file`, `model=saaras:v4`, `mode=transcribe`, `language_code=unknown` for detection or an explicitly selected supported code | JSON `text`, `language_code`, `model=bulbul:v4-flash`, `output_audio_codec=wav` or `mp3`; optional compatible stock `speaker` |
| Success | `transcript`, detected `language_code` or null, optional confidence metadata | `audios` array of base64-encoded audio strings |
| Provider limit | 30 seconds per REST request | 2,500 characters per REST request |

[Speech-to-text REST reference](https://docs.sarvam.ai/api-reference/speech-to-text/transcribe) · [Text-to-speech REST reference](https://docs.sarvam.ai/api-reference/text-to-speech/convert)

- **STT.** Saaras v4 is the current recommended REST model. It supports 22 Indic languages and English, including Indian and Global English. `transcribe` keeps the spoken language and may normalize numbers and formatting. `verbatim` is available when fillers and repetitions matter. Use plain transcription for the draft. The mode named `translate` renders English, while `translit` renders Latin script. Select a recording format the browser actually supports, such as WebM/Opus or MP4/AAC. REST also accepts WAV, MP3, M4A, OGG, AAC, FLAC and other documented containers. For raw PCM the codec field is required and the sample rate is 16 kHz. Reject empty recordings and stop capture below the provider's hard 30-second limit. The public 500 MB file limit belongs to a different product flow and should not size the short REST integration. [Saaras model and formats](https://docs.sarvam.ai/api/api-guides-tutorials/models/saaras) · [REST formats and MIME types](https://docs.sarvam.ai/api/api-guides-tutorials/speech-to-text/overview)
- **TTS.** Send `language_code`, as shown in the current REST wire schema. Use `en-IN` for English. Bulbul v3 remains the model default when omitted, so pin the chosen model. V4 Flash expects a compatible persona ID such as `simran_en_customer`, or can use its default `shubh_enhi_ads`. V3 uses short stock IDs such as `shubh`. WAV is the reference default and MP3 is explicitly supported. Decode the selected codec, validate the result and serve its matching MIME type. Skip `opus`, pitch, loudness, and explicit preprocessing or cache switches for the v3/v4 REST request. Preprocessing is automatic on those models. [Bulbul REST parameters](https://docs.sarvam.ai/api-reference/text-to-speech/convert) · [Audio format guidance](https://docs.sarvam.ai/api/api-guides-tutorials/text-to-speech/how-to/set-audio-format-for-output)
- **Language coverage.** Bulbul's dedicated model catalog says the v4 Flash voice catalog currently lacks Malayalam and Odia even though its general best-practices guide lists eleven language codes. Use the specific model catalog for selection. If playback in `ml-IN` or `od-IN` is required, the v3 catalog lists both. Pin the compatible voice/model pair. UI, speech recognition and playback each have their own language coverage. [Bulbul model language support](https://docs.sarvam.ai/api/api-guides-tutorials/models/bulbul#language-support) · [Bulbul v4 best practices](https://docs.sarvam.ai/api/api-guides-tutorials/text-to-speech/best-practices)

Keep provider keys and outbound calls in the authenticated backend. Use separate per-actor and process admission bounds, server-side format and size checks, a finite request deadline and one provider dispatch per explicit action. Handle 402 as exhausted credits, 429 as throttling and service errors as temporary unavailability. Preserve typed drafts and on-screen text on failure. The first smoke should use a short synthetic recording and short approved text, assert no record changes, and verify playback in the browser and Android WebView separately. If the provider is unconfigured, keep the typed flow available and report the speech feature as unavailable. [API errors](https://docs.sarvam.ai/api/getting-started/errors-troubleshooting) · [Provider limits](https://docs.sarvam.ai/api/getting-started/pricing#rate-limits)

## Price and production use

Sarvam lists pay-as-you-go STT at **₹0.49/minute**, billed per second. The public price table currently lists v4 Flash at **₹1 per 1,000 characters** during a 50% promotion through 12 November and shows **₹2** as its base. The API documentation lists ₹1 without surfacing that promotion end date. Bulbul v3 is **₹3 per 1,000 characters**. Use the workspace billing page for the actual account rate. Public prices exclude GST. As an illustration, 20 seconds of STT plus 500 synthesized characters costs about ₹0.66 at the displayed promotion or ₹1.16 at the displayed v4 base rate, before GST. The public PAYG REST limit is 60 requests per minute for each speech API, shared at the account level. GlucoFlow's app-level bounds should be smaller. [Sarvam public pricing](https://www.sarvam.ai/api-pricing) · [Billing and rate-limit documentation](https://docs.sarvam.ai/api/getting-started/pricing)

Sarvam's commercial licensing guide says managed TTS output may be used in shipped products when generation consumes credits on the customer's account under its terms. The ₹100 verification credits count, so the documentation does not require a paid top-up or a separate production license purchase solely to use the generated audio. API calls still consume credits. This grant concerns generated output. Stock voices and model rights remain governed by Sarvam's license, and voice cloning introduces separate consent requirements. Use stock voices for GlucoFlow. [Commercial licensing](https://docs.sarvam.ai/api/getting-started/commercial-licensing) · [EULA](https://www.sarvam.ai/eula) · [Terms of Service](https://www.sarvam.ai/terms-of-service)

## Retention and data handling

The STT product page advertises no training and zero retention after processing. Sarvam's general Privacy Policy describes an opt-out mechanism for model improvement and a configurable content-retention default of 30 days after last access. The policy excludes certain business customer content governed by separate agreements. The workspace docs offer a **No retention (0 days)** override for **Model APIs**, with prospective effect. They list different retention controls for managed Voice Agents. These public statements do not establish the settings or agreements of a particular workspace. Record the effective speech API workspace terms, retention setting and training choice before considering non-synthetic content. [STT product claims](https://www.sarvam.ai/try/speech-to-text-transcription) · [Privacy Policy](https://www.sarvam.ai/privacy-policy) · [Workspace retention](https://docs.sarvam.ai/api/platform/data-retention)

Use ephemeral audio buffers for recording and playback. Clear the clip after the response or cancellation and revoke browser playback URLs. Keep clips, transcripts, text sent for synthesis, generated audio and provider keys out of diagnostics. Save an edited user submission only through the application's ordinary authenticated workflow. Report the app's actual persistence separately from provider-side processing. The synthetic demo does not establish any healthcare data processing or residency guarantee.

## Sarvam as a possible Hermes provider

Sarvam offers **Voice Agents (Samvaad)**, a managed product with conversational orchestration, tools, knowledge and telephony. It also offers **Token Factory**, which serves OpenAI-compatible inference and documents function calling and structured output. The REST speech calls above use the Model APIs only. Hermes remains responsible for GlucoFlow's guarded source reads, extraction, record planning and proposals. [Voice Agents overview](https://docs.sarvam.ai/voice-agents/overview) · [Token Factory](https://docs.sarvam.ai/api/token-factory)

For a separate synthetic model evaluation, Sarvam documents base URL `https://api.sarvam.ai/v2` and `POST /v2/chat/completions`, with Bearer authentication supported. `sarvam-105b` is a text-only reasoning candidate for language-heavy Ask and record planning. Its conversation-tuned sibling is also text-only. For the native document-image route, the catalog lists `glm5.3-flash`, `gemma4` and `deepseekv4.1-flash-1017` as text-plus-image models. These IDs identify Sarvam-hosted models. They are distinct from a model ID used at another provider's API. [Model catalog](https://docs.sarvam.ai/api/getting-started/models) · [Chat Completion V2](https://docs.sarvam.ai/api-reference/chat/chat-completions-v2)

Treat any model change as an adapter and evaluation task. Verify the exact message and function schemas, output caps, storage flags, image handling, SDK usage and provider retries under the current [Hermes wire guards](../hermes/runtime.py). Sarvam's reasoning trace can consume the output cap, and defaults vary by model. Require source-citation, clinical-refusal, tenant-isolation, multilingual and latency checks before substituting a model. The official Sarvam Agent Skills are coding references. Their speech examples can lag the current wire schema and do not grant runtime approval or clinical authority. [Sarvam Agent Skills](https://docs.sarvam.ai/api/developer-tools/agent-skills)

## Implemented and measured, 7 November 2026

The authenticated API now provides bounded transcription and reviewed read-aloud, with a server-only credential and durable deployment-wide admission budgets. Initial caps are 60 seconds of transcription and 1,000 synthesis characters in total; these are conservative reservation counters, not actual provider invoices. Per-request limits are 30 seconds and 500 characters, with one provider attempt and a finite timeout. Failed attempts keep their reservation. Audio/transcript content is not written to the budget table. Provider retention remains `workspace_setting_unverified`.

The [live synthetic proof](../reports/sarvam-live-proof-2026-11-07.json) made two authenticated in-process backend calls: 65 Hindi characters synthesized in 1,508 ms, then the resulting 4.075125-second clip transcribed in 455 ms with the expected sentence preserved. This is not a hosted browser microphone test or broad recognition-quality benchmark. No patient record was submitted.

The client exposes dictation as an editable draft in Care Ask and patient visit notes. Review and insert remain separate from sending. Read-aloud requires explicit review/generation and does not autoplay. The UI locale reaches Hermes directly, while controlled prose currently has English/Hindi templates and explicit English fallback elsewhere. Speech uses the reply's actual language. Odia/Punjabi service aliases are mapped at the boundary; document locale tags retain their proper scripts.
