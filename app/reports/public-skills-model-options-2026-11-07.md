# Public workflow skills and model options

Sources checked 7 November 2026. This research used public documentation and repository files. It made zero provider calls and installed zero external skills. GlucoFlow's deployed baseline is Hermes v0.23.0 with `gpt-6-luna`. The [deployment record](care-deployment-2026-11-07.md) documents one successful hosted source-grounded turn at 44.203 seconds after a timeout adjustment. That result combines runtime startup, tool steps and provider time.

## Model choice for synthetic care coordination

Prices are in USD per million text tokens. OpenAI figures use Standard short-context rates. DeepSeek publishes two time-dependent rates.

DeepSeek peak hours are 01:00–04:00 and 06:00–10:00 UTC on weekdays, excluding Chinese public holidays. Flash costs less than either Sol on the quoted token rates. Luna costs less than Flash for uncached input and output even at Flash's off-peak rate. Flash has a lower cache-hit rate. As an illustration, 1,000 turns with three calls each, 4,000 uncached input tokens and 650 billable output tokens per call would cost about **$2.18 Luna**, **$43.50 either Sol**, **$5.94 Flash peak**, or **$2.97 Flash off-peak**. These are identical-token estimates, not measured costs. The actual mix of cache, reasoning tokens and calls per accepted turn can change the ranking. [OpenAI pricing](https://developers.openai.com/api/docs/pricing) · [DeepSeek pricing](https://api-docs.deepseek.com/quick_start/pricing/)

**The adapter decides what is usable.** GlucoFlow currently pins Chat Completions, the model endpoint and two function tools. Its process enforces a three-request maximum, output and input byte bounds, and an accepted typed reply. A reasoning-enabled Sol or any 6.1 Sol tool run needs a Responses-aware request validator and tool-output mapping. The exact older Sol can be a same-transport comparator with explicit `none`. Account entitlement, GlucoFlow accuracy and Sol latency are unmeasured. [GlucoFlow wire guard](../hermes/runtime.py) · [OpenAI GPT-6 transport guidance](https://developers.openai.com/api/docs/guides/latest-model#update-api-and-model-parameters)

For a future Flash trial, start with explicit `reasoning_effort: "none"` or `thinking.type: "disabled"`, documented `max_tokens`, and the same synthetic questions. Verify all request fields, including the app's OpenAI-specific `store` and `parallel_tool_calls` settings, against a local protocol fixture first. DeepSeek's Chat reference does not document those two fields. In thinking mode the tool sequence must replay the returned `reasoning_content` or DeepSeek reports HTTP 400. Keep that field in transient provider protocol state only. The Responses implementation is stateless, ignores its `parallel_tool_calls` and `max_tool_calls` switches, and requires the app to enforce the serial tool budget. The official Hermes integration guide covers upstream setup and uses V4 Pro in its example. It establishes neither GlucoFlow compatibility nor an existing Flash credential. [DeepSeek Chat API](https://api-docs.deepseek.com/api/create-chat-completion/) · [Thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/) · [Responses API](https://api-docs.deepseek.com/guides/responses_api/) · [Upstream Hermes integration](https://api-docs.deepseek.com/quick_start/agent_integrations/hermes/)

For this workload, keep Luna while measuring phase latency, model-call count, billable input/output and the share of correct, source-grounded answers. A paired Flash disabled/low test is the first useful alternative if it improves the cost per accepted turn or tail latency. Compare `high` or `max` only on a named failure set whose operational ambiguity warrants extra reasoning. Use an explicit call and spend budget, exact evidence matching, stale-feed and cross-encounter negatives, and a fixed stop after scoring. Reserve Sol for a demonstrated quality gap. The Flash-1017 weights are MIT-licensed, with self-hosting capacity and costs still unmeasured for this project. [DeepSeek model card](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017)

## Curation and bounded improvement

- **Start with four app-owned procedures.** Cover exact-order specimen receipt and result acknowledgement, stale or corrected evidence, shift handover and source inspection, and approval/attestation versus source-confirmed completion. Use concise, typed coordination rules. For diabetes, display documented values, dates, units and provenance under existing human-review boundaries.
- **Pin and review the text.** For each adopted idea record its source URL, commit, license, approved reviewer, evidence prerequisites, exact scope, allowed tool names and regression fixtures. Start with the two existing care tools and the app's authorization and state machine. The [Agent Skills specification](https://agentskills.io/specification) permits supporting scripts and assets. The care deployment should admit only its own reviewed content and typed data.
- **Keep self-improvement to one bounded review action.** A reviewer may request one draft coordination change from redacted, accepted outcomes. Require one explicit draft and one fixed evaluation pass against unseen synthetic scenarios, with deterministic gates for actor isolation, source evidence, stale feeds, cancelled orders and clinical requests. Human approval publishes an immutable version to a permitted scope. Retire a version by explicit action and preserve its review history. The live process continues to enforce its two-tool and three-provider-call caps. Avoid scheduled candidate generation, open-ended retries and runtime writes to skill files. [GlucoFlow memory audit](agent-memory-audit-2026-11-07.md)

This research distinguishes published capabilities from deployment evidence. Only Luna has measured live GlucoFlow results in the existing release. A credible Flash or Sol choice needs a paired workload benchmark on the same synthetic source and policy contract.
