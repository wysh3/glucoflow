# Health-a-thon scope audit and pilot plan

7 November 2026. Scope is controlled by the six supplied FAQ screenshots, identified below by their question headings. This assessment uses the working tree during the removal pass and separately dated synthetic verification. It is an engineering and submission audit. No site pilot or clinical outcome was measured. [Official programme](https://healthathon.reskilll.com/) · [Programme evidence in the repository](../../docs/research/2026-11-03-strategy/01-hackathon-brief.md)

## Decision for the submission

Show one ward-to-lab workflow. A nurse has documented collection. A lab receipt is still unverified. The assistant retrieves the exact order and source, proposes a time-bounded watch, and a person approves it. A matching lab receipt closes the watch. A stale feed, staff attestation and a confirmed receipt have visibly different states. Use synthetic events and built-in synthetic documents. Lead with this handoff, with report upload and chart review as a separate way to show document intake.

The core supports an assistive demonstration. The whole reachable demo still needs a scope pass before claiming alignment with the FAQ. The strongest gaps are older clinical interpretation cards, arbitrary user-supplied data on the public demo, and the lack of a measured baseline or ward/lab pilot.

## Primary KPI — specimen handoff lag

**Question.** Does the workflow reduce the time between a documented collection and a matching lab receipt without losing or misclassifying evidence?

| Definition | Proposed measurement |
| --- | --- |
| Eligible cohort | One chosen ward, one receiving lab, one common specimen class selected with the site, all consecutive eligible collections on predeclared comparable shifts. Use one observation per physical specimen, with a specimen-level source key. An order can contain more than one specimen. An order cancelled before collection has no eligible start. A cancellation after collection remains visible as a separate outcome. |
| Start and end | Start at the authoritative HIS or collection-register time when staff recorded collection. End at the first valid LIS or accession-register receipt for that same specimen. Use source `occurredAt` semantics and a common clock/time zone. Keep entry and ingestion times for capture QA. A human attestation, message, assistant reply, late import time or task click does not qualify as a receipt. |
| Calculation | For verified pairs, lag minutes = `(receipt time − collection time) / 60 seconds`. Report median as the single primary summary and the 90th percentile as a diagnostic. Compare intervention median minus baseline median in minutes using the same source rules and predeclared follow-up window. Show eligible collection count, number of verified pairs, no receipt, cancellations after collection, ambiguous matches, and invalid/missing timestamps in both phases. If missingness or case mix differs substantially, mark the median comparison inconclusive and show the change in verified receipt coverage separately. |
| Reconciliation | Deduplicate repeated source rows by exact specimen and event reference. Preserve corrections. Quarantine mismatched specimen/clock records for human review without inventing timestamps. Close both cohorts with the same observation window, set by the site before analysis. Never turn no receipt into a zero-minute handoff. |
| Collection, access and cadence | Site quality lead owns the definition and weekly review. Ward and lab designate source owners. Use existing approved collection and accession extracts or a two-column register cross-check. Compute linked durations and keep source identifiers in the hospital. Release only fully anonymised aggregates or validated anonymised material to hackathon systems, mentors and demos. |
| Drivers and guardrails | Track source-match coverage and manual chase calls/minutes per eligible specimen. Audit false source closure, duplicate work, loss of staff control and any unauthorized data use. Report added staff effort and observed operating cost per 100 eligible handoffs, split into staff time, model use and hosting. Keep source SLA compliance and clinical outcomes out of the primary claim. |

The baseline will determine a useful target and sample requirement. Set both with the site before the comparison. A decrease accompanied by lower verification coverage or unresolved safety failures is an inconclusive result for expansion. The current simulator contains the source event pair and timestamps needed to rehearse the definition. Its seeded intervals are fabricated. ## Proposed 60–90 day pilot

| Days | Work | Evidence and decision |
| --- | --- | --- |
| **1–15** | Name ward, lab and quality owners. Select the specimen class and shifts, review current register fields, agree collection/receipt definitions, participant languages and opt-in requirements, and document exceptions and existing downtime workflow. Establish the fake-only separation and the site's approvals before any observational work. | Site acceptance, data-flow map, permissions, predeclared denominator, clock quality and actual weekly volume. Proceed only if the same specimen can be identified reliably and the site can retain any real source data internally. |
| **16–35** | Baseline under usual practice. The site captures consecutive eligible specimens and checks time and identity quality using the existing workflow. Staff run synthetic prototypes on site with stale, duplicate, mismatch, cancel and pause cases. | Site-computed anonymised baseline median, tail, coverage and staff effort, with the data-quality exclusions. Fix scope and declare the minimally useful change before intervention. No synthetic time enters the site baseline. |
| **36–60** | Shadow and usability. Rehearse the app with fictional or verified fully anonymised material while the site continues its ordinary handoff. Validate local-language usability where needed, task override, explicit status and audit. The hospital validates any minimal export internally. | Observed staff completion, friction and error cases in the real setting. These establish feasibility. A patient-linked pilot requires a distinct, site-approved environment and processing protocol. Leave the hackathon/demo environment on fake-only inputs. |
| **61–90** | With approvals and verified source quality, run a small ward/lab operational comparison, preferably with parallel comparable shifts, otherwise the same weekday and shift mix before and after. Preserve standard care, clinician responsibility, and an immediate manual fallback. A site-owned measurement process computes eligible handoffs and anonymised aggregate outcomes. | Compare median, tail, coverage, extra work, audit failures and cost using the frozen definition. State small counts and changes in shift or case mix. Report a go/no-go decision. If real-setting comparison cannot start, report feasibility and baseline only. |

The pilot timeline is proposed. No partner, baseline, effect size, sample size or care outcome is represented as achieved. An approved research or care setting does not change the requirement to keep patient data out of the hackathon platform, mentor materials and demos.

## Implemented follow-up

The audit's derived clinical dashboard findings were removed: no automatic low-glucose alert, eGFR-decline interpretation or diagnostic reference panels. Tracking intervals and manual categories start unassigned; follow-up dates remain null without explicit input. Source values, human review, override and audit remain. Sarvam speech is now implemented and one synthetic Hindi round trip was measured. Native patient language catalogs have explicit partial-coverage notices. These improvements do not establish full multilingual coverage, real caregiver delegation, pilot evidence or government certification.
