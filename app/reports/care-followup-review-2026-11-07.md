# Independent review of the care follow-up

This review covers the local follow-up source for operational skills, workspace recovery and episode navigation. The earlier hosted release has its own [deployment record](care-deployment-2026-11-07.md). The checks here used synthetic fixtures, a local database and a mocked sidecar. A new hosted release and Android device behavior were outside this review.

## Findings and resolution

- **P1, fixed.** The API bridge accepted an approved skill proposal for encounter B with no citation, A's event as its only citation, or both A and B. The response card would display those citations alongside the B proposal. The bridge now requires the exact target order's collection event or current validated/corrected result event and rejects other citations in a skill-proposal reply. The runtime normally emitted the correct evidence and the application preview independently recomputed B's evidence. The bridge check now defends both of those boundaries. Multi-encounter overviews can still cite multiple encounters. [Bridge validation](../apps/api/src/care/chat.ts#L79) · [Red/green cases](../tests/integration/care-hermes-bridge.test.ts#L46)
- **P2, episode links depend on the active workspace.** `?encounter=` survives reload with the correct workspace already active. A copied link opened in another browser, or after reopening a different workspace, cannot select the original workspace and shows Episode unavailable. This is a navigation limitation. The drawer searches only the authorized active workspace, so the link discloses no other workspace data. [Episode lookup](../apps/client/src/features/care/episode.tsx#L10) · [Active workspace recovery](../apps/client/src/features/care/use-care-workspace.ts#L29)
- **P2, freshness inside the episode drawer.** The modal shows both last-sync timestamps and explains that missing events remain unknown. The explicit connected, stale and disconnected indicators are on the parent surface. A stale or disconnected feed is easier to recognize if the same indicators appear in the modal. Server preview and monitoring still enforce freshness. [Episode timeline](../apps/client/src/features/care/episode.tsx#L48) · [Skill preview](../apps/api/src/care/skills.ts#L160) · [Monitor](../apps/api/src/care/monitor.ts#L64)

## Verified boundaries

- A local two-identity API walkthrough passed. A signed-in non-clinician captured and sandbox-tested a skill from a source-confirmed event in A. Their approval returned HTTP 403. A different authenticated clinician could not open A's workspace and could approve the shared template from their own workspace. Its response contained no A event ID or private origin pointer. The approved template produced a B proposal with B's own collection event. Human approval and a separate B receipt were required for source-confirmed completion. This demonstrates separately attributable participation. The policy also permits a clinician who created a draft to approve it. [Origin and clinic RLS](../supabase/migrations/046_care_operational_skills.sql#L1) · [Capture and approval](../apps/api/src/care/skills.ts#L122) · [Version review](../apps/api/src/care/skills.ts#L273)
- One active version is enforced per clinic and pattern. A transaction advisory lock serializes version allocation, publication and application. Application checks the current version, B's matching event and both feeds again under the lock before creating an approval request. Retirement blocks new application of that version while existing tasks preserve their version and history. The recorded origin is historical provenance from capture time. [Version lock](../apps/api/src/care/skills.ts#L107) · [Application](../apps/api/src/care/skills.ts#L219) · [Unique active version](../supabase/migrations/046_care_operational_skills.sql#L35)
- The recovery endpoint returns owner-filtered summaries and reauthorizes each workspace read. Recovery and skill queries include the signed-in actor in their cache keys. The workspace subtree remounts on identity changes, workspace polling aborts on unmount, and session clearing drops the query cache. The source preview also rejects an evidence ID from the wrong encounter or order. ## Measurement and scope

- The combined care API and mocked bridge run passed **20/20**. The Python policy unit run passed **12/12**, including the exact-order skill annotation, wrong or ambiguous scope, stale feed, cancellation and correction cases. The client skill evidence and OpenUI unit run passed **7/7**. TypeScript passed after the bridge fix. The full browser gate and live provider smoke are separate checks.
- The feature selects between two fixed operational templates. It captures a successful synthetic outcome and proposes reuse with fresh evidence and human approval. It does not train a model, invent a procedure, enable autonomous skill or clinical rule editing, or let staff jointly browse one patient's private simulation. Sharing is clinic-scoped. Hospital unit/assignment policies, independently scheduled monitoring, external notifications, device verification and clinical validation remain outside the demonstrated result.
