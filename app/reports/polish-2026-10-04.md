# Glucoflow clinic polish — 4 October 2026

The public demo has a warm mint clinic theme, working navigation icons, responsive cards and dialogs, patient actions above long charts, and a built-in synthetic PDF library. Reviewers can choose Clinic team → Try a sample report → Upload lab sample → Review this report without finding their own documents.

## Changes and audit fixes

- Three clearly labelled, invented PDFs cover a normal lab report, missing patient identifier and mismatched patient. They enter the ordinary upload/extraction pipeline. Repeated uploads resolve older duplicate chains to the original report instead of leaving reviewers at a duplicate dead end. Worker deduplication selects only original reports with an available review, avoiding unfinished uploads and new duplicate chains.
- Patient corrections open a prefilled editor, require a change, show a preview and preserve previous versions.
- Publication has a green confirmation, approval revision and a direct link to approved records. Published review mutations are disabled while source evidence remains readable.
- Glucose and symptom timestamps are independent. Timestamp display uses the local calendar date; printed report dates remain date-only. Exported notes explicitly state IST; blood-pressure labels are complete.
- Scenario assignment is explicit for the primary synthetic patient, preventing another clinic with the same identifier from inheriting it. Migration 018 was applied locally and to hosted storage without changing historical migration checksums.
- Snapshot downloads use an authorized, patient-scoped API and private, expiring storage URLs. Supabase's HTTP 400 / embedded 404 missing-object response is handled without swallowing permission failures. The hosted private exports bucket now allows PDF and JSON while retaining its 15 MiB limit.
- Mobile safe areas, readable form sizes, compact role cards, softer surfaces and distinct navigation SVG icons were improved. Demo patients consistently land at Home readings.

## Live walkthrough

On `https://glucoflow.vercel.app`, Clinic team opened the sample library, uploaded the lab sample and inspected its original PDF. The live worker extracted five values: HbA1c 7.1%, fasting glucose 124 mg/dL, eGFR 72 mL/min/1.73m2, systolic pressure 132 mmHg and diastolic pressure 82 mmHg. Each was checked against the source and explicitly reviewed. Publication succeeded at revision 9 and appeared in the approved timeline. A later repeat upload displayed Already uploaded, opened that same original review and retained its publication confirmation and disabled draft mutations.

At a 390 × 844 mobile viewport, the patient workspace had a 390-pixel content width with no horizontal overflow. All five navigation items contained SVG icons. Home entry forms and shortcuts appeared before the long scenario charts.

Live SOS checks exposed and resolved two hosted-storage differences: missing-object response encoding and the PDF-only MIME allowlist. After those changes, the download API completed, the UI showed no error, and the resulting signed storage URL returned HTTP 200 with valid JSON, the expected snapshot ID, a digest and `emergencyDispatch: false`. The in-app browser did not emit a downloadable-file event for the Blob link, so a saved hosted browser file was not independently confirmed there. The equivalent desktop/mobile Chromium workflow did save and validate the JSON in automated tests.

API is running `20261004-polish2` and worker `20261004-polish4` images, with Azure provisioning state `Succeeded`; Vercel production aliases the updated client to `glucoflow.vercel.app`.
