## Production blockers and order

1. **Separate the public demo from real records.** The web demo build includes reusable synthetic role credentials. Same-account saved workspaces are intentionally shared, and document, note and assistant surfaces can accept and persist arbitrary operator content. Use separate synthetic infrastructure and individually provisioned identities for any real deployment. Require patient-assignment and purpose checks, deletion/retention policies, read audit, incident response and approved model egress before using personal records. This is independent of the ABDM registration blocker. [Demo credentials build](../scripts/deploy-care-web.py#L49) · [Owner workspace persistence](../apps/api/src/care/repository.ts#L33) · [Privacy audit](privacy-implementation-audit-2026-11-07.md) · [ABDM readiness](abdm-india-readiness-2026-11-07.md)
2. **Close two SQL privilege gaps before trusting the receipt proof.** A read-only local catalog query confirmed PUBLIC execution ACLs on both the internal `result_event` and the global-capable `escalate_overdue_results`, and effective EXECUTE for `sutra_api` and `sutra_worker`. Migration 022 revoked PUBLIC execution on the original seven-argument helper. Migration 035 replaces it with a nine-argument `SECURITY DEFINER` helper that takes a caller-supplied actor and has a default ACL. An additive migration can revoke EXECUTE on the new signature from PUBLIC and the API role while preserving calls from owner-executed transitions. Regression-test direct denial for both runtime roles and ordinary transitions, including their proof chain. The catalog finding identifies an available SQL privilege. This audit did not demonstrate an external HTTP path to the helper. [Original revoke](../supabase/migrations/022_result_event_guard.sql#L1) · [Current helper](../supabase/migrations/035_obligation_lifecycle.sql#L153)
3. **Split global escalation from scoped escalation and unify state.** The current function accepts a null clinic and skips its membership check. The in-process timer uses that path as `sutra_api`. Preserve a non-null, membership-scoped wrapper for any retained HTTP action. Move the global invocation to a separately authorized durable scheduler and revoke PUBLIC/API access to the global helper. Stage the timer cutover with the grant change. The ordinary worker uses `sutra_worker` and its document-queue scaler can stop the replica, so copying the timer into that process alone provides no no-traffic guarantee. Separately, the legacy closure writes `status='closed'` without setting the new `terminal_state`, and the global function filters on `terminal_state`. That allows an overdue legacy-closed row to remain eligible for auto-escalation. Reconcile and test state before turning on scheduled production escalation. Queued notification rows establish a queue record. Delivery is a separate capability. [Current timer](../apps/api/src/server.ts#L116) · [Global function](../supabase/migrations/041_escalation_stage_clock.sql#L6) · [Legacy close](../supabase/migrations/031_result_closure.sql#L592) · [Worker role](../apps/worker/src/main.ts#L90) · [Replica policy](../scripts/deploy-care-azure.py#L150)
4. **Use fixed operational error codes and bounded execution at public edges.** Fastify strips the query string and redacts auth but returns mapped PostgreSQL error messages verbatim and logs raw exception messages for 5xx. Worker failure handling also logs and persists raw exception messages, and the job DTO exposes the stored text. Keep useful intentional domain messages through explicit safe mapping and test the generic path against sensitive-looking provider, storage and database errors. Apply deliberate edge and actor quotas to public and authenticated work, including demo workspace creation and storage growth. Guide and Hermes hourly counters are process-local; they reset on restarts and cannot enforce a shared spend limit. Preserve the durable per-document budget. [API errors](../apps/api/src/errors.ts#L79) · [API error logging](../apps/api/src/server.ts#L59) · [Worker errors](../apps/worker/src/main.ts#L154) · [Job DTO](../packages/data/src/jobs.ts#L293) · [Hermes limiter](../hermes/server.py#L244) |
5. **Make release gates reflect the deployed paths.** Current checked-in CI applies PostgreSQL migrations, runs TypeScript tests and builds JS. It does not cover native Hermes tests or the Linux worker runtime, browser workflows or Android. The web script can publish directly to the production alias and scans known private values, while the Azure script validates digests and polls for a ready revision. Before any pilot, require an immutable build and independent readiness checks for database, model configuration and upload worker, plus tested rollback, restore, and access/retention operations. The database-only API readiness endpoint can stay cheap. Check dependencies separately in the release gate. [CI workflow](../../.github/workflows/ci.yml) · [API readiness](../apps/api/src/routes/health.ts#L13) · [Azure deployment check](../scripts/deploy-care-azure.py#L190) · [Web deployment path](../scripts/deploy-care-web.py#L72)

Sequence the reductions by dependency. First remove disconnected presentation and duplicate internal code. Retire shared APIs only after moving their consumers and preserving evidence. Do not edit applied migrations to make the repository look smaller. Production readiness is a separate acceptance gate from the synthetic demo's web or Android checks.

## Implementation follow-up

The findings above describe the audit baseline. Migrations 048 and 051–053 now close the direct result-event and global-capable escalation ACL findings, attribute explicit escalation to the current actor, exclude legacy-closed rows and correct the typed-row invocation. The unscoped in-process timer was removed; unattended external delivery is not promised. Migration 050 removes implicit seven-day follow-up assignment. Migration 049 adds durable deployment-wide speech reservations. Delta/body-map client callers and assets are removed; persisted history remains. Global guide/Hermes spend accounting and the other production controls above are not thereby certified complete.
